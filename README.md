# Rhymes Music — сайт лейбла

React + Vite + Supabase + Vercel. Designed by cookiekiller.online.

## Запуск
```bash
npm install
npm run dev              # разработка
npm run lint             # ESLint: recommended + react + react-hooks (exhaustive-deps: error)
npm run build            # продакшен-сборка в dist/
npm run build:artifact   # один HTML-файл в dist-artifact/ для превью в Claude
```

Сайт — неофициальный концепт, сделанный в подарок лейблу; это сказано в футере
и в `og:description`.
Без переменных окружения сайт работает на локальных данных из `src/data/content.js`
(демо-пароль пресс-кита: `demo`, заявки открываются письмом на sales@rhymesmusic.com).

## Supabase
1. Выполнить `supabase/schema.sql` в SQL Editor.
2. Скопировать `.env.example` в `.env`, вписать URL и anon key.
3. Залить данные: `SUPABASE_SERVICE_ROLE_KEY=... npm run seed`.
   По умолчанию seed бережный: добавляет новых артистов и записи каталога, которых в базе
   ещё нет (релизы — по названию, клипы — по id, концерты — по дате и городу), а у существующих
   релизов дописывает пустые дату и обложку. Ничего не удаляет и не перезаписывает правки из админки.
   Запускайте его после каждого обновления каталога в `content.js`. `npm run seed -- --force`
   заменяет ручные записи каталогом (найденное синхронизацией не трогает).
   Вакансии и люди из `content.js` — примеры: заливаются с `published = false`.
4. Пресс-кит: `supabase secrets set BACKSTAGE_PASSWORD_HASH=<sha256 пароля>`,
   `supabase functions deploy backstage`, файлы положить в бакет `backstage/<slug>/`
   и описать в таблице `backstage_files`.

## Деплой
Vercel подхватывает проект как Vite, `vercel.json` отвечает за SPA-роутинг.
Переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` добавить в настройках проекта.

## Структура
- `src/components/Player.jsx` — сквозной плеер: превью + анализ звука, иначе Spotify embed
- `src/components/StageLights.jsx` — WebGL-свет для артистов без фото
- `src/components/Lineup.jsx` — «Собрать лайнап» для организаторов (кнопки «+» только на /booking)
- `src/components/Cursor.jsx` — курсор: точка, кольцо с инерцией, магнит у кнопок
- `src/components/Gigs.jsx` — концерты по месяцам и карточка ближайшего концерта
- `src/components/Filters.jsx` + `src/lib/useFilters.js` — фильтры на нативных select
- `src/components/Social.jsx` — соцсети иконками
- `src/components/JobList.jsx`, `src/pages/Job.jsx` — вакансии и страница вакансии `/jobs/:slug`
- `src/lib/api.js` — слой данных (Supabase или локальные данные)
- `src/lib/format.js` — числа, даты концертов, плюрализация

## Соглашения
- Состояние, которое нужно соседним слоям, — классом на `<html>` через `useRootClass`:
  `nav-hidden` (табы артиста встают под шапку), `has-player` и `has-tray`
  (футер и плашка лайнапа освобождают место). `:has()` не используем.
- Hover-эффекты карточек — внутри `@media (hover: hover)`: на тач-экранах они залипают.
- Даты концертов разбираются в полдень (`parseISODate`), «сегодня» — по локальному времени.

## Автозаполнение страниц артистов

Edge Function `supabase/functions/sync-catalog` каждые 6 часов проходит по артистам
с `auto_sync = true` и заполняет их страницы. Чтобы добавить артиста, достаточно
`slug` и `name` — остальное функция найдёт сама.

| Блок | Откуда | Как попадает на сайт |
| --- | --- | --- |
| Фото, подпись по жанрам | Spotify (профиль артиста) | только если поле пустое |
| Об артисте | ru.wikipedia, первые предложения статьи | только если био пустое; рядом ссылка на источник |
| Ссылки Spotify, YouTube | найденные источники | добавляются к соцсетям, если их нет |
| Релизы | Deezer (обложки 1000 px, точные даты) и Spotify (ссылки для плеера) | сразу; скрыть — `releases.hidden` |
| Популярное | Spotify (Extended Quota) или рейтинг Deezer | сразу, по популярности |
| Клипы | YouTube: канал артиста и канал лейбла | сразу; скрыть — `videos.hidden` |
| Концерты | афиши из `tour_sources` (schema.org Event), Bandsintown | на модерацию (`status = 'pending'`) |

**Deezer** не требует ключей: публичный API отдаёт обложки, даты и популярность треков
даже там, где Spotify в Development Mode молчит. ID артиста — из ссылки `deezer.com/artist/<id>`.

**Как находятся источники.** Если `spotify_id`, `deezer_id`, `youtube_channel_id` или `wikipedia_title`
пустые, функция ищет их по имени и берёт только точное совпадение (у Spotify — самого
крупного из совпавших, у Википедии — статью, где в описании певец, рэпер, группа…).
Не нашлось — повторит через неделю. Всё найденное автоматически видно в представлении
`artists_autodetected`: проверьте, что привязались нужные артисты, и при ошибке впишите
правильный id вручную — ручное значение функция не трогает.

**Что функция не перезаписывает.** Заполненные вручную фото, подпись, био и соцсети;
скрытые релизы и клипы; статус и данные ручных концертов. Дубли отсекаются по ссылкам
и названиям, в том числе против записей, внесённых вручную.

### Подключение (один раз)
1. Выполнить обновлённый `supabase/schema.sql` (блоки идемпотентные).
2. Spotify: создать приложение на developer.spotify.com, взять Client ID и Secret.
3. YouTube (для клипов): ключ YouTube Data API v3 в Google Cloud Console.
   ID канала лейбла — из ссылки `youtube.com/channel/UC…`.
4. Секреты функции:
   ```bash
   supabase secrets set SYNC_SECRET=<длинная случайная строка> \
     SPOTIFY_CLIENT_ID=... SPOTIFY_CLIENT_SECRET=... \
     YOUTUBE_API_KEY=... LABEL_YOUTUBE_CHANNEL_ID=UC...
   # необязательно:
   supabase secrets set BANDSINTOWN_APP_ID=... AUTO_PUBLISH_SOURCES=bandsintown
   ```
5. `supabase functions deploy sync-catalog --no-verify-jwt`
6. Расписание: выполнить `supabase/cron.sql`, подставив адрес проекта и `SYNC_SECRET`.
7. Первый прогон сразу, не дожидаясь расписания:
   ```bash
   curl -X POST "https://<project>.supabase.co/functions/v1/sync-catalog" -H "x-sync-secret: $SYNC_SECRET"
   ```
   Первый прогон по всем артистам займёт пару минут. Итог — в ответе и в таблице `sync_runs`.

### Как добавить артиста
Supabase Studio → Table Editor → `artists` → новая строка: `slug`, `name`, `palette`.
По желанию сразу укажите `spotify_id` и `tour_sources` (страницы с концертами артиста —
его сайт или страница на билетном сервисе). Без них страница заполнится после
ближайшего запуска, кроме концертов: для них нужны `tour_sources` или `bandsintown_name`.

### Модерация
- Концерты: представление `concerts_pending`; опубликовать — `status = 'published'`, отклонить — `hidden`.
- Автонайденные источники: представление `artists_autodetected`.
- Журнал запусков с ошибками по каждому источнику — `sync_runs`.

### Тесты
```bash
deno test supabase/functions/sync-catalog   # 13 тестов чистой логики разбора
```

## Админка (/admin)

Профили артистов редактируются на самом сайте: `https://<домен>/admin`.
Работает только с подключённым Supabase.

**Доступ.** Вход по почте и паролю пользователя Supabase Auth с ролью admin:
1. Supabase → Authentication → Users → Add user (почта и пароль).
2. SQL Editor:
   ```sql
   update auth.users set raw_app_meta_data = raw_app_meta_data || '{"role":"admin"}'
   where email = 'name@rhymesmusic.com';
   ```
3. Выполнить обновлённый `supabase/schema.sql`: он создаёт бакет `artists` для фото
   и права «только админ пишет». Без роли admin войти можно, но изменить ничего нельзя.

**Что можно:**
- Добавить артиста: имя (адрес страницы создаётся сам), подпись, био, фото, цвета, соцсети.
  Новый артист — черновик, на сайте появится после галочки «Показывать на сайте».
- «Создать и заполнить автоматически» — сохранить и сразу запустить синхронизацию:
  подтянутся Spotify, YouTube, Википедия, релизы, популярное, клипы, концерты.
- Поправить автонайденное: если синхронизация привязала не того артиста, вставьте
  правильную ссылку на Spotify или YouTube.
- Удалить артиста (с подтверждением по адресу страницы).

### Фото артиста: размер

| | |
| --- | --- |
| Формат кадра | горизонтальный, **3:2** |
| Рекомендуемый размер | **2400 × 1600 px** |
| Минимум | 1600 × 1067 px (меньше — админка не примет) |
| Файл | JPG, PNG или WebP до 20 МБ |
| Что делает сайт | уменьшает до 2400 px по длинной стороне и сохраняет в WebP (~300–600 КБ) |

Одно фото показывается в трёх кадрировках: шапка на компьютере (16:9), шапка на
телефоне (узкая вертикаль) и карточка в списке (4:5). Поэтому:
- артист по центру, лицо в верхней трети кадра, вокруг — запас фона;
- без текста и логотипов: поверх кладётся имя;
- после загрузки нажмите на фото в то место, которое должно оставаться на виду
  при обрезке (или двигайте ползунки) — ниже сразу видно все три кадрировки.

Проверки админки: `npm test` (логика формы, разбор ссылок, размеры фото).

### Место в Supabase
Вверху админки — сколько места всего по тарифу, сколько занято и сколько свободно,
отдельно для файлов (фото) и базы данных, с разбивкой по бакетам и самым большим таблицам.
Занятое место считает функция `admin_usage()` в базе (доступна только админу), поэтому цифры
реальные. Лимиты тарифа база не знает — их задаёт переменная окружения:

| Переменная | Значение |
| --- | --- |
| `VITE_SUPABASE_PLAN` | `free` (по умолчанию: база 500 МБ, файлы 1 ГБ) или `pro` (8 ГБ и 100 ГБ) |
| `VITE_DB_LIMIT_MB`, `VITE_STORAGE_LIMIT_MB` | необязательно: точные лимиты, если они отличаются |

Перед загрузкой фото админка проверяет, хватает ли свободного места.

## Обслуживание

- **`supabase/schema.sql` идемпотентный**: после каждого обновления проекта выполняйте его целиком,
  повторный запуск безопасен. Проверено на PostgreSQL 16: три запуска подряд и обновление старой схемы.
- **Spotify.** С марта 2026 приложения в Development Mode не получают топ-треки, followers и popularity.
  Релизы синхронизируются в любом режиме; «Популярное» — только при `SPOTIFY_EXTENDED_QUOTA=true`
  (нужен Extended Quota Mode). Если в Spotify несколько артистов с тем же именем, синхронизация
  не угадывает: в админке у артиста появится список «Это он».
- **Синхронизация пачками**: за вызов — `SYNC_BATCH_SIZE` артистов (по умолчанию 6), дольше всех
  не обновлявшихся; cron раз в 30 минут (`supabase/cron.sql`, можно запускать повторно).
- **Заявки**: длина полей, скрытое поле-ловушка и не больше 5 заявок за 10 минут с одного IP — проверяет база.
- **sitemap.xml**: задайте `SITE_URL` в переменных Vercel — файл соберётся перед `npm run build`.
- **Проверки**: `npm run lint`, `npm test`, `deno test supabase/functions/sync-catalog`.

### Пресс-кит
Админка → карточка артиста → «Пресс-кит»: файлы (райдеры, stage plot, промо-фото, био) и, при
желании, свой пароль артиста. Админка → «Сайт → Пресс-кит»: общий пароль для всех артистов без
своего и сводка по артистам. Пароли хранятся только как bcrypt-хеш (функции `set_backstage_password`,
`check_backstage_password`), файлы — в приватном бакете `backstage`, организаторы получают ссылки на
30 минут. После обновления передеплойте функцию `backstage` (`supabase/functions/backstage.bundle.ts`
вставляется в редактор Supabase Dashboard так же, как `sync-catalog`).

### Проверки качества
`npm run lint` (ESLint), `npm test` (unit-тесты), `npm run unused` (knip: неиспользуемые файлы,
экспорты и зависимости), `deno test supabase/functions/sync-catalog`.
